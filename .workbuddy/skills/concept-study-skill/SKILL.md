# concept-study-skill

## 一、适用场景

适用于**需要快速建立对某个专业概念的初步理解并形成可复习的个人笔记**的场景，包括但不限于：

- 课程作业中遇到不熟悉术语（如 "Transformer"、"MapReduce Shuffle"、"反向传播"），需要先形成自己的理解再深入
- 自学一门新课程前，先对核心概念做"鸟瞰式"梳理，建立后续深入阅读的锚点
- 复习备考时，把零散资料整理成统一结构、方便反复翻阅

**不适用**：

- 需要严谨学术定义或论文级细节 → 应当直接读教材/论文
- 单一事实查询（"X 是什么年份提出的"）→ 搜索引擎即可，不需要六段结构
- 涉及医疗/法律/金融等高风险决策 → 必须由专业人士复核，不依赖本 Skill 的输出

## 二、输入信息要求

调用方需要提供以下信息（缺一不可）：

1. **概念名称**（必填）：用最常见的中英文术语，例如「Transformer」「MapReduce」「反向传播」「L1 正则化」
2. **所属领域**（必填）：让 Skill 知道从哪个知识体系切入，例如「机器学习」「分布式系统」「编译原理」
3. **学习目标**（必填）：例如「理解其工作机制」「能向同学讲清楚」「为后续做实验打基础」
4. **学习者背景**（选填但强烈推荐）：如「有 Python 基础但没学过分布式」「了解 CNN 但不熟 RNN」，没有则写"零基础"

可选：

- **重点关注子方向**：比如「希望侧重工程实现而非数学推导」
- **字数/深度偏好**：例如「简短入门级（800 字内）」「中等深度（1500-2500 字）」

## 三、生成执行步骤

调用方收到输入后，按以下顺序执行：

1. **概念澄清**：用一句话给出工作定义（含必要的限定条件），避免一上来就堆砌术语
2. **结构化拆解**：按"概念个人理解 → 核心机制 → 应用场景 → 容易混淆点 → 公开来源 → 自测题"六段填充
3. **资料检索**：用 WebSearch / WebFetch 检索 ≥ 3 条**公开可核查**来源（官方文档、教材章节、维基百科、技术博客均可），避免引用无法访问或私域内容
4. **写作风格**：以"个人学习笔记"口吻写，避免 AI 套话（「在当今..."，"具有重要意义」等）；多用具体例子、少用空泛概括
5. **自检**：对照第五节"自检校验要求"逐条过一遍，不通过就改
6. **交付**：把结果写成一个 Markdown 文件到指定路径，文件名建议 `<concept>-notes.md`

## 四、输出固定结构

无论什么概念，输出都按以下六段呈现：

| # | 段落 | 内容要点 |
|---|------|---------|
| ① | **概念个人理解解释** | 一段工作定义 + 一段"如果我向朋友解释我会怎么讲"的口语化版本 |
| ② | **核心机制/组成** | 用层级或分点列出 3-6 个关键要素，说明它们如何协作；可配 ASCII 图或 Mermaid |
| ③ | **真实应用场景案例** | 至少 2 个具体例子（来自公开资料），说明"谁在哪用、解决了什么问题" |
| ④ | **容易混淆点、使用边界限制** | 列出 2-5 个易混点或边界条件；明确"什么情况下不能用/不适用" |
| ⑤ | **可核查公开参考来源链接** | ≥ 3 条 URL + 简短说明"为什么这条来源可核查"（官方？教材？论文？） |
| ⑥ | **自测思考题** | 3-5 道题（理解类、应用类、分析类混合），每题附参考答案要点 |

## 五、资料来源要求

- **必须可核查**：所有引用都能打开、能定位到原话或原图
- **优先级**：官方文档 / 教材章节 > 权威技术博客 > 维基百科 > 个人博客（最后一种只用作辅助）
- **禁止引用**：付费墙后的内容、未公开的内部资料、AI 自己编造的内容（即使是"看起来很像"的引用）
- **时效性**：涉及版本号/年份的事实（如 API 改动），尽量引用最近 2 年内的来源

## 六、自检校验要求

生成完毕后，必须对照以下清单自检，不通过则返工：

| 检查项 | 通过条件 |
|--------|---------|
| 六段齐全 | ①②③④⑤⑥ 全部存在且不空 |
| 没有 AI 套话 | 不出现"在当今…"、"具有重要意义"、"赋能"、"不可或缺"等空话 |
| 来源全部公开 | ⑤里所有 URL 可点开；不少于 3 条；至少 1 条是官方/教材 |
| 例子具体 | ③里的案例有具体的人/公司/产品/论文，不是泛泛"很多公司都在用" |
| 边界明确 | ④里至少有 1 条"不适用场景" |
| 自测题有答案 | ⑥里每题都有参考答案或要点提示 |
| 术语一致 | 全文术语翻译一致（如 "Embedding" 全文统一为"嵌入"或"Embedding"，不要混用） |
| 字数合理 | 总体在调用方声明的偏好范围内 |

通过以上 8 项后，才把文档交给调用方。
